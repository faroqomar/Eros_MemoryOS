## Memory configurations

Wax stores and retrieves documents. `Memory.save` does not extract facts with a language model. The current default embedding selection uses E5 for new stores; its bundled E5-small-v2 and MiniLM choices do not establish Arabic semantic retrieval. The lexical baseline must say lexical. A later semantic arm needs a reviewed multilingual embedding provider, explicit vector readiness and a measured Arabic/Iraqi Arabic test. Preserve source IDs in metadata and keep canonical originals outside the `.wax` index. [Wax Swift app description](https://github.com/christopherkarani/Wax/blob/67da356544e145a02f97fcf9cf6be39a199ced74/README.md#swift-app), [E5 model card](https://huggingface.co/intfloat/e5-small-v2), [MiniLM model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2).

Cactus Engine provides execution, embedding, RAG and vector-index C APIs. A Cactus memory arm needs an app-owned adapter, a pinned supported embedding asset and a stable source-ID mapping. It does not replace MemoryOS originals, correction history or relationships. Compare retrieval configurations separately from text-generation runtimes so a language-model change cannot masquerade as a retrieval improvement. [Cactus C API](https://github.com/cactus-compute/engine/blob/2204770dfd8c85750aaa20d25b657194becfc4c4/cactus-engine/cactus_engine.h).

**Initial Cactus integration blocker:** both pinned release `v2.2.2` (`2cfcdb8568eb9192323b27fd0012a834517b4419`) and inspected main have `cactus_engine.h` include `cactus_graph.h`, while `apple/build.sh` copies only `cactus_engine.h` into framework headers. The official repository issue reports the resulting Swift import failure. Do not claim the advertised XCFramework compiles as shipped. The initial research did not patch Cactus; C39 later authorized the required integration repair below. [Pinned release header](https://github.com/cactus-compute/engine/blob/2cfcdb8568eb9192323b27fd0012a834517b4419/cactus-engine/cactus_engine.h), [pinned release header-copy script](https://github.com/cactus-compute/engine/blob/2cfcdb8568eb9192323b27fd0012a834517b4419/apple/build.sh), [upstream issue #771](https://github.com/cactus-compute/cactus/issues/771).

The separate current `cactus-compute/cactus` main repository now describes Python 4.x and points to prebuilt runtime libraries for iOS ARM64 and simulator. Those libraries load Needle 3, Whistle and Mirage `.cact` assets. They are a different API/product path from the general Cactus Engine Swift/RAG binding above. Do not combine the two versions' APIs or licenses. [Current Python README](https://github.com/cactus-compute/cactus/blob/44f8e0ec1ec71dddf028e7c37635cce01b3cdcc5/README.md), [runtime platform table](https://huggingface.co/Cactus-Compute/cactus/blob/main/README.md).

## Licenses, privacy and adoption limits

Wax uses Apache 2.0; llama.cpp and MLX Swift LM use MIT. Qwen3 assets above use Apache 2.0. Check the complete resolved dependency graph and model notices before adoption. Preserve relevant notices with redistributed artifacts. [Wax license](https://github.com/christopherkarani/Wax/blob/67da356544e145a02f97fcf9cf6be39a199ced74/LICENSE), [llama.cpp license](https://github.com/ggml-org/llama.cpp/blob/master/LICENSE), [MLX license](https://github.com/ml-explore/mlx-swift-lm/blob/3.32.3/LICENSE).

Cactus Engine has a custom source-available license. It permits personal/research and defined organizational use; an organization must remain below both USD 2 million funding and gross annual revenue thresholds or obtain a separate license. Treat commercial eligibility as unresolved for a future business. The Python 4.x repository's Apache license does not relicense Engine v2.2.2. [Engine license](https://github.com/cactus-compute/engine/blob/2204770dfd8c85750aaa20d25b657194becfc4c4/LICENSE).

Engine includes hybrid cloud routing and telemetry surfaces. A local evaluation must omit credentials, disable network/telemetry paths, use explicit local-only options, reject a `cloud_handoff` response and verify airplane-mode operation. Merely omitting an API key does not prove that no request leaves the phone. The current Python 4.x README also documents anonymous usage counts and `CACTUS_TELEMETRY=0`; do not assume that environment variable governs the older native engine. [Engine hybrid documentation](https://github.com/cactus-compute/engine/blob/2204770dfd8c85750aaa20d25b657194becfc4c4/docs/cactus_hybrid.md), [current Python telemetry statement](https://github.com/cactus-compute/cactus/blob/44f8e0ec1ec71dddf028e7c37635cce01b3cdcc5/README.md).
