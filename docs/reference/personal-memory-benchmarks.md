## Priority candidates

### RHELM: strongest first fit for heterogeneous personal recall

- [Paper](https://arxiv.org/abs/2605.31086), [author repository/evaluator](https://github.com/microsoft/RHELM), [official dataset card/files](https://huggingface.co/datasets/microsoft/RHELM). Public data and evaluation code exist; generation-pipeline availability is a separate question.
- The card lists 10 fully synthetic personas, 1,305 QA pairs, dated conversations, emails and document attachments. English. Questions cover facts, time, aggregation, hallucination, misleading requests, attachments and mixed sources; labels include supporting turn/file evidence.
- Best fit: entity disambiguation, misattribution, preference conflicts, contradictory premises and changes across journals, reports and chats. The paper uses binary answer accuracy and an additional quality score; the supplied runner uses OpenAI/Azure credentials.
- Limits: simulated lives and mostly answerable QA do not establish authentic relationship understanding, motive accuracy or calibrated confidence. Dataset card and repository differ on some taxonomy/statistic totals; pin the exact release rather than merging their counts.
- Licenses: dataset CC BY 4.0; code MIT. Retain attribution and record modifications. Inspect source assets before redistribution.

### LoCoMo-Plus: useful second axis for implicit context

- [Paper](https://arxiv.org/abs/2602.10715), [author repository/evaluator](https://github.com/xjtuleeyf/Locomo-Plus), [data instructions](https://github.com/xjtuleeyf/Locomo-Plus/blob/main/data/README.md). The repository exposes cognitive cue/trigger samples, context-construction scripts and evaluation code.
- English synthetic/adapted conversations. Adds cognitive questions to LoCoMo: connect an earlier implicit state, cause, goal or value to a later query with different wording. It tests applying relevant context, beyond retrieving matching words.
- The supplied framework uses an LLM judge for constraint consistency and supports API-backed scoring. Freeze construction inputs, insertion choices, prompts and judge; the paper distinguishes task-dependent judgment rules.
- Limits: the authors exclude long-term belief revision, emotional dynamics and multi-agent memory. Success cannot certify romantic-conflict advice or true motives. Small, constructed cases and judge sensitivity limit generalization.
- Licensing hold: no top-level license appeared in the inspected author repository. Its LoCoMo base carries CC BY-NC 4.0. Obtain clear permissions for the extension and intended commercial-development use before adopting or redistributing it; public visibility supplies no reuse grant.

## Broader personal insight and real conversations

**PersonaMem-v3: released, broader, with substantial adaptation cost.** [Paper](https://arxiv.org/abs/2608.21381), [author code](https://github.com/bowen-upenn/PersonaMem-v3), [data card/backend files](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v3), [evaluation specification](https://github.com/bowen-upenn/PersonaMem-v3/blob/main/EVAL.md). The arXiv record shows July 16 submission and October 7 revision, 2026. Public code and data exist; it is not paper-only.

The authors ground generated cross-platform worlds in anonymized real engagement histories; these are not verbatim real relationship archives. Tasks cover personalization, recommendation, changing preferences, restrained use of personal information and proactive/tool actions. The English card describes 100 released personas; the paper/repository overview describes a 200-user foundation. Preserve that distinction and timestamp masking. Native media/raw platform records are unavailable.

Code is MIT; [data and derived personas are CC BY-NC 4.0](https://github.com/bowen-upenn/PersonaMem-v3/blob/main/LICENSE). The published runner calls model APIs and an LLM judge. EVAL.md lists removed/merged tasks and paper-sync gaps: pin the actual release and scoring rules. Treat hidden-persona labels as benchmark construction, not psychological truth. Candidate for later restraint/insight research after rights review; feed ranking and autonomous actions exceed the smallest current suite.

**RealCompanion: closer real-history evidence, access-gated.** [Paper](https://arxiv.org/abs/2610.01780) describes 10 real human–AI relationships, 27,218 messages and source-linked profile/persona/chat/QA labels. The [English dataset card](https://huggingface.co/datasets/Quislab/RealCompanion) requires individual reviewed access and a custom agreement. It bars product/commercial use, training and redistribution; evaluation indexes must be deleted after each run. The paper links an [anonymous code/reproduction repository](https://anonymous.4open.science/r/realcompanion-54CC/), but its contents were not readable in this inspection. Do not call this an unrestricted runnable suite. Small, selected human–AI relationships also differ from human–human conflict histories. Defer.

## Smallest useful proposal

1. Start with a fixed, stratified **RHELM pilot** across people/project attribution, time/change, contradictory premises, missing evidence and mixed sources. Keep its original English questions, contexts, source IDs and scoring; publish the selected IDs/counts. A pilot score is not the full benchmark score.
2. Add a small **LoCoMo-Plus cognitive slice after license clearance** to test implicit causes, states, goals and values. Until then, use independently authored fictional cases for that axis. Add LongMemEval v1 knowledge-update/abstention cases only when the selected RHELM cases leave those distinctions uncovered; retain a separate score.
3. Keep a separate **MemoryOS app suite** in English, Iraqi Arabic and mixed language: repeated names, speaker swaps, tentative versus confirmed plans, later corrections, sarcasm, one-sided/missing messages, competing interpretations and irrelevant-memory rejection. Include project scope as well as relationships. Author fictional source passages with expected evidence and acceptable uncertainty; treat insight alternatives as hypotheses.

For the app suite, measure evidence retrieval recall/precision, citation support, attribution errors, stale-fact use, unsupported assertions, correct abstention/clarification and interpretation restraint. Report each dimension; recall accuracy alone cannot establish insight quality. Score source citation and counterevidence independently from the original benchmark's answer score.

Keep official benchmark results, selected pilots, translations, changed judges and app adaptations in separate reports. Translated/rewritten items require bilingual review and new labels; do not present their scores as published English results. Hold out fresh cases and split by persona/history where feasible; repeated diagnosis cases are regressions, not unseen qualification.

Run any later app evaluation offline through app-owned interfaces. Hosted reference evaluators are separate research dependencies and require a separate approved data flow; a local replacement judge changes comparability. Use public permitted or fictional data only. Do not send private archives to judges, seed training with them, enable cloud fallback or weaken existing quality gates. Measure device cost separately from semantic quality.
