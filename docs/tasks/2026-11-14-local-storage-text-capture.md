Concrete action trace: `CaptureView` forwards Save to `LocalRecordsViewModel.saveCapture`; the ViewModel passes the unmodified text to injected `LocalMemoryUseCases.create`; the use case validates it and calls `RecordRepository`; the actor `SQLiteRecordRepository` commits the canonical source row. The ViewModel clears only the submitted draft after commit, retains text typed during the operation, and treats a committed write as success even if the following snapshot fails, preventing duplicate retries. Corrections and link/Trash actions follow the same direction. `LocalRecordRules` in MemoryCore owns correction/link/deletion rules. Picker Views forward URLs; `RestoreArchiveFromFile` calls the injected `ArchiveDataReader`, and the app's `LocalArchiveFileReader` bounds/security-scopes the file read before repository restore. Views/ViewModels import no SQLite, storage adapter, network or provider SDK. `LocalStoreComposition` constructs the adapter and injects these use cases. Independent review still must inspect these actual paths.
